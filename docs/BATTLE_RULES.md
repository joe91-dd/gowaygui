# 战斗模拟器说明

文件：`game/assets/scripts/core/battle.ts`。模块只依赖 `core/types.ts`、`data.ts` 与 `random.ts`，没有 Cocos、DOM、系统时间、浏览器存储或全局随机数依赖。UI、动画与声音消费事件，不能反向决定伤害。

## 接口与恢复

```ts
createBattle(levelId, wave, [{ id, turtle, level, slot }], { seed?, coreHealth? }): BattleState
stepBattle(state, dtSeconds): BattleState
getBattleEvents(state): BattleEvent[]
commandBattle(state, { type: 'cast', unitId, skillId }): boolean
```

`stepBattle` 原地推进并返回同一状态；只按 0.05 秒固定 tick 结算，帧间余数也保存在状态里。`getBattleEvents` 消费当前事件，不改变战斗结果。所有状态均可 JSON 序列化，含随机数、下次普攻时间、主动冷却、护盾、控制窗口、吸血滚动记录、来源、敌人位置与波次。事件不包含 `undefined`，重启后同一 tick 与输入可得到逐字段相同的状态。

状态包含 `levelId`、`wave`、`status: fighting | won | lost`、`elapsed`、`coreHealth`、`units` 与 `enemies`。单位和敌人均提供 `id/x/z/hp/maxHp/alive`；单位额外提供 `slot/role/skills/shield`。每个技能的激活次数保存在 `skillActivations`，供测试和非玩家调试工具审计，不用它代替真实效果。

视图事件包括 `attack/heal/skill/damage/spawn/defeat/leak/waveEnd/shield/control`。通用字段有 `sourceId/targetId/skillId/amount/x/z`；伤害事件标明暴击和二次效果。敌人首领技能用 `effect: crabSlam | crabSummon`。事件队列最多保存 4096 条；UI 应每帧消费。经济收益由 GameService 按波次结算，战斗事件自身不发金币。

新波使用 `createBattle`，传入上一波剩余核心耐久和服务当前存活个体列表。本波倒地龟不再行动或接受治疗，下一波重新生成时满血恢复；不会销毁永久收藏。替补由局外编排层管理，模拟器只接收最多五个不重复占位的上阵个体。

## 数值与职业规则

- 攻击、生命按照讨论稿的资质及成长公式计算；防御仅使用资质系数。所有已拥有的合法技能均进入计算，最多十二项，不存在前六项或隐含装备上限。
- 物理和法术分别用护甲与法抗减伤。先减抗，再比例穿透，有效抗性最低为零。普通伤害基础暴击率 5%、倍率 150%，治疗不暴击。
- 肉盾最多阻挡两只敌人。射手单体物理攻击。法师主目标 100%、半径 1.5 格内最多两个不同目标各 40%。治疗优先生命比例最低的伤者。控制每第三次普攻使目标减速 25%、持续两秒。
- 默认按条件自动释放职业主动，普攻与主动共用动作占用时间。主动占用 0.4 秒，冷却来自 `data.ts`。手动请求不能绕过冷却、目标合法性或动作占用。
- 敌人按路线距离行进，优先攻击阻挡自己的肉盾。远程敌人每次开火只暂停 0.3 秒，随后继续路线，避免永远停在肉盾攻击范围外产生僵持。吐墨螺第三次攻击带三秒 15% 虚弱，给净化提供实际可应对的场景。
- 巨钳蟹每第三次攻击震击附近最多三名友军，附带 0.8 秒眩晕；半血时一次召唤两只小怪，不额外发经济奖励。首领硬控先乘 0.25。
- 核心初始 20，普通漏怪扣 1、精英扣 3、首领扣 10；扣到零失败。最后一个计划敌人已生成且场上没有活敌人时本波胜利。

## 三十技能的防循环规则

静态类强壮、硬壳、抗魔、快手、远望直接改变真实属性。稳定缩短敌人眩晕。自愈必须连续五秒未受伤后按秒恢复，护盾吸收的攻击也中断无伤计时。开场盾六秒，自保四秒且每波一次；所有护盾累计不超过目标最大生命 40%。

鼓劲半径 4.5 格，只加成一名最近友军；多个来源优先避免重复覆盖，目标最终最多获得 8%。格挡只处理敌人直伤。分担保护 4.5 格内最近友军，取一次直伤在护甲与格挡之后的 10%，转移给保护者；转移部分不再次减伤，不触发格挡、分担或反伤。反伤只计算近战直伤造成的真实生命损失，按 15% 直接返还，同攻击者 0.5 秒最多一次；反弹不再减伤、暴击或触发吸血。未标记平衡版本的历史波次继续使用 3 格辅助范围，下一波才采用新值，见 [范围第二版](BATTLE_RANGE_V2.md)。

吸血与吸魔只计算直接伤害造成的真实生命损失，排除过量、护盾、弹射、溅射、连击追加弹和反伤。每个来源保留最近一秒治疗记录，滚动上限为最大生命 2%，不是按自然秒重置。连击第五次普攻追加一发 60%，追加弹不推进计数。穿甲弹 240% 并忽略 70% 剩余护甲。

弹射从主目标之外选一个敌人，30% 法术伤害，不再触发溅射或弹射。破魔的 5 点减抗只刷新不叠加，且不回溯加强触发它的那一击。水晶炮单体 320%。

双重治疗必须选择另一个受伤友军，按基础治疗值 35% 结算。治疗盾仅取有效治疗的 15%。净化每八秒最多清除一个负面，优先眩晕、定身，再处理减速、虚弱和减抗；有负面但满血的友军仍可被净化。大治疗有人低于 60% 时全队回复施法者攻击 220%，不复活本波倒地者。

破甲减少 8 点护甲，虚弱降低攻击 8%，均刷新而不叠加。定身每第六次普攻触发。泡泡圈半径 1.5 格最多五敌人。敌人八秒控制窗口内时长依次 100%、50%、25%，之后免疫至窗口结束。同名减速取最高，普通减速上限 60%。

上述新增敌人动作时长与吐墨螺/首领技能是当前可测试的实现参数；其数值仍需整体平衡和视图预警验证。

## 布阵与仿真范围

布阵会产生实际差异。第二版射手 4.8、法师/控制 4.6、治疗 4.5 的范围修正了第四关首个阻挡点的火力缺口和位置 4 的普通治疗隔离；路线与站位保持。石龟仍须靠近道路才能阻挡，治疗也未改成全场覆盖。准备阶段提供选择龟的范围提示。旧范围的几何诊断保存在 [第四关覆盖审查](FOURTH_LEVEL_COVERAGE.md)，不能把旧值导致的问题当作当前布阵规则。标准模拟策略仍为 `stone=1, spike=0, crystal=2, leaf=3, bubble=4`（零基位置）。

单元测试中的固定五人四技能队伍只用于规则与数值回归，不作为真实新手流程的完成证据。下面联调报告使用真实初始收藏、逐波招募与服务等级；它是当前首通测量依据。

## 真实 GameService 联调仿真

`game/tools/simulate-chapter.cjs` 使用真实 `GameService`、`SaveRepository` 和战斗模块，不在脚本里代替服务发资源、升级或招募。初始五只永久收藏均为两技能、三项资质 76、成长 1.00；首波只有射手入场，每次波间最多加入一只，局内等级、随机新增技能均读取服务状态。每关末仅收录服务已经产生、技能数超过原收藏的个体；没有直接赠送四技能全队。

每波第 2.375 秒保存并完全重建服务，将恢复结果与未中断模拟对比。调用使用绑定 `runId` 的 `beginWave(commandId,runId,battle)`、`checkpointBattle(commandId,runId,battle)` 和 `completeWave(commandId,runId,finishedBattle)`；不能手写胜利结果跳过真实战斗。重复波次结算使用同一命令编号验证无重复奖励。报告同时保留可由 `decodeSave` 校验的六份存档封套，位于 `docs/reports/chapter-simulation`。
