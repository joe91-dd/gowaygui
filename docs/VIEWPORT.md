# 窗口适配检查

游戏以1280×720横向构图制作，使用Cocos SHOW_ALL。2026年9月8日实际窗口由1280×720缩到372×864及689×864后，旧版UI只显示中央部分；点击区域和画面也不再按完整构图呈现。

根因是GameEntry手动把Canvas.alignCanvasWithScreen关闭，同时固定UI正交相机orthoHeight=360。Cocos Creator 3.8.8的canvas.ts（_onResizeCamera）原本会用screen.windowSize.height / view.getScaleY() / 2更新正交高度，并将相机对齐Canvas世界中心。恢复该公开属性后，保留Canvas中心(0,0)和原有界面坐标即可按SHOW_ALL完整展示。

三维相机仍使用竖直视角。窄窗口将垂直视角改为 `2 * atan(tan(基础视角/2) * max(1, (16/9)/窗口宽高比))`；基础首页38度、战斗42度。这样横向设计视野在窄窗口不被裁去，宽窗口仍保持原有垂直视野。只监听canvas-resize及design-resolution-changed，不重建菜单、不改变选队、战斗或随机状态。

战斗站位按钮通过实际主相机投影，坐标再按Cocos视图缩放还原到以原点居中的UI。擦泡泡触点继续使用getUILocation（引擎已扣除SHOW_ALL视口留白），与1280×720构图坐标一致。

构建20260908-125721已成功并通过构建产物回归。实际689×864窗口中，首页、关卡、选队、招募和战斗均完整呈现；水晶龟从第一站位移到第三站位再移回第一站位成功。普通关第四波后实际合成叶子龟，横向擦除上半区显示50%，再擦下半区进入对比页；技能说明弹窗、关闭和暂不收录均正常。第五波后的本地模拟广告刷新实际改变招募候选，按钮随即禁用；随后加入第五位伙伴并通过第六波。

窄竖窗完整呈现不等于手机竖屏体验已设计完成；正式手机版本仍以横屏触控布局验收。

后续加入窄竖窗提示：Canvas下拆为可清理的“当前页面”和独立提示节点，主页面/弹窗切换不销毁提示。手机显示旋转建议，桌面窄窗显示加宽建议；提示放在游戏构图下方留白，按实际像素保持约17px文字，不覆盖战斗点击区域。设计原点和UI相机仍保持原约定。20260908-143905实际689×864首页、详情、第三关战斗和招募弹窗已看到完整提示，无重叠；该容器改动后的站位点击另行实测。

同构建后续实测：第三关第二波之间，选中水晶龟后点击第三站位，模型与卡片位置从1变为3；再点击第一站位移回成功。招募收藏叶子龟后重载到152027构建，当前局保持。152027首页在689×864与随后变窄的332×864均完整呈现；更窄窗口字小是SHOW_ALL横向构图的实际限制，独立提示仍可读，不能将此称为竖屏成品体验。
