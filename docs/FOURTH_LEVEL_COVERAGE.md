# 第四关「薄暮海湾」站位、支援与拦截点覆盖核查

日期：2026-09-08。对象：`levelId=3` 当前原始路线与五站位；界面编号使用 **1–5**，程序 `slot` 使用 0–4。本轮没有修改生产代码、场景、存档或关卡数据。候选仅供后续平衡评估，不是运行验收。

## 已证实的结论

1. 位置 1 与位置 2 距离是 **4**，不是 5。叶子龟在位置 2 可以普通治疗位置 1 的石头龟；基础治疗 4 和初始「远望」后的 4.3 都够。
2. **位置 4 是普通治疗的孤立站位。** 它距位置 2、3 均为 `√20=4.472136`；叶子龟放这里，初始 4.3 范围无法治疗任何其他站位。自疗仍可用。其他位置的初始叶子龟也无法普通治疗位置 4。
3. **「石头龟位置 1、水晶龟位置 2」存在最前段的直接火力断层。** 石头龟在敌人进入 1.2 阻挡圈时就把它挡住，不会等敌人走到站台正侧面。理论首个拦截点距水晶龟 **4.586844**，超过法师基础 4、远望后 4.3，连射手基础 4.5 都略差；射手有远望达到 4.8 则可以覆盖。
4. 当前五个固定位置之间最短距离为 **3.605551**，所以 3 格「鼓劲」和「分担」在任何两格之间都没有友军目标。该判断只针对当前布局，不能扩大到所有关卡。
5. 「大治疗」是全场存活上阵龟的远距离补救，但并非初始技能，且受到触发门槛与 28 秒冷却限制，不能代替普通治疗布局。

## 代码口径与技能边界

`game/assets/scripts/core/data.ts` 的 `ROLES`、`SKILLS`、`LEVELS` 以及 `core/battle.ts` 为唯一战斗数值来源。具体审查版本的 SHA-256 在原始 JSON 中，避免后续修改后把行号视作版本锚点。

| 行为 | 当前实际口径 |
|---|---|
| 石头龟阻挡 | `updateMovement`：固定 `ROLES.stone.range=1.2`，每只最多同时挡 2 个；没有模型半径补偿。远望只加攻击范围，不加阻挡范围。 |
| 射手 / 法师 / 控制 | 基础 4.5 / 4 / 4；远望各加 0.3。等级、资质、成长不会自然增加范围。 |
| 叶子龟普通治疗 | 基础 4，初始技能含远望，实际 4.3；仅选存活且受伤或有可净化状态的对象，按生命比例优先，可选自己。 |
| 双重治疗 | 第二个不同伤者仍由同一叶子龟、同一范围重新选取，治疗量 35%；不是经第一个对象接力延伸。 |
| 大治疗 | 有任一存活上阵龟生命比例 **严格低于 60%** 才触发；全场所有存活上阵龟恢复施法者有效攻击的 220%；不查距离，不能复活，不作用于替补。技能自动触发，手动请求也不绕过门槛或冷却。 |
| 水晶普攻溅射 / 弹射 | 首个目标必须在自己范围内；之后溅射在命中点 1.5 内最多额外 2 个，各 40%；弹射按命中点至另一敌人的距离选一个 30% 目标，因此可以间接命中施法者范围外敌人。 |
| 水晶炮 / 穿甲弹 / 泡泡圈 | 仍先要有施法者射程内的直接目标；泡泡圈再以该目标为中心扩展 1.5。不能把效果半径直接加到首个目标选择半径。 |
| 鼓劲 / 分担 | 当前新波次读取 `BATTLE_RULES.encourageRange=3` / `shareRange=3`；无版本号的旧快照保留原 3 格规则。下表按当前新波次计算。 |

相关函数：`createBattle`、`updateAuras`、`updateMovement`、`targetEnemy`、`targetPatient`、`basicAttack`、`castSkill`、`damageUnit`。只看模型看起来相邻或攻击特效够远，不能证明数值范围已覆盖。

## 治疗可达图和石头龟阻挡能力

| 位置 | X / Z | 普通治疗 4 或 4.3 能达到的其他位置 | 距路线中心最近距离 | 石头龟 1.2 能挡路 | 阻挡覆盖路线总长 |
|---|---|---|---:|---|---:|
| 1 | -5 / 1 | 2 | 1.000000 | 是 | 0.773731 |
| 2 | -1 / 1 | 1、3 | 3.000000 | 否 | 0 |
| 3 | 3 / 1 | 2、5 | 1.414214 | 否 | 0 |
| 4 | 1 / -3 | 无 | 1.000000 | 是 | 1.326650 |
| 5 | 6 / -1 | 3 | 1.000000 | 是 | 1.326650 |

友军图是 `1—2—3—5`，另有孤立的 `4`。图连通不等于一只叶子龟能治疗整个连通分量；单只只能治疗自己的直接邻居。

这不是要求把位置 2、3 移到近战范围内。它们原本可以承担远程/辅助用途。明确问题是：玩家把肉盾放在哪、谁能治疗肉盾、谁能打到肉盾实际拦下的敌人，这三件事必须同时检查。

位置 4 的肉盾能挡路，但当前其他位置的普通治疗不够；位置 5 的肉盾只有位置 3 的普通治疗可达，远程有效支援也集中在位置 3。有限站位会导致治疗与火力争用支援格，不能只凭其中一项覆盖就称阵型完整。

## 当前 core 的确定性复现

执行方式：

```powershell
& 'C:/Users/Administrator/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe' docs/reports/fourth-level-coverage.cjs
```

脚本只在进程内转译、加载当前 TypeScript，并写入 `docs/reports/fourth-level-coverage.*`。不加载存储仓库、不访问浏览器 localStorage、不运行 Cocos。可用 `TYPESCRIPT_JS`、`SHARP_ROOT` 指向已有本地依赖。

条件：第四关第二波，石头龟位置 1、水晶龟位置 2；各自初始技能；两只局内等级 1，三项资质均 80、成长 100、训练为 0，固定战斗种子 `20260908`，每步 0.05 秒。**这是明确的诊断阵容，不冒充主线程实际收藏龟的完整数值。**

| 观测 | 实际输出 |
|---|---|
| 首次出现被挡敌人 | tick 47，2.35 秒，`enemy-2-1` 快跑蟹 |
| 被挡位置 | `(-5.4298755995, -0.1074688999)`，路线 s=3.68 |
| 到石头龟 / 水晶龟距离 | 1.1879732300 / **4.5662112512** |
| 当时水晶普攻次数 | **0** |
| 水晶首次普通攻击 | tick 447，22.35 秒，直接目标 `enemy-2-3` |
| 同 tick 的范围外间接伤害 | 对被石头龟挡住的 `enemy-2-2` 造成 17.28 溅射伤害；该敌距水晶龟 4.0030135，大于直接射程 4 |
| 这个单样本最终结果 | 33.5 秒胜利、核心 20、5 击败 / 0 漏怪；石头龟剩余生命 142.67214，水晶剩余 259.2 |

因此三层结论必须分开：**初始被挡目标不可被法师直接选择**已经证实；**后续有目标走入范围时可产生间接输出**也已证实；**整波必败或零输出**不成立。这个单样本胜利也不能用作整体平衡已通过的证明。

另有 5 个一步纯内存治疗诊断：延后敌人生成 1000 秒，只设置友军生命刺激，然后执行真实 `stepBattle`，不是实战波次胜率测试。

- 叶子位置 4、其余四只半血：普通治疗 0 次。
- 叶子位置 2、位置 1 和 3 半血：普通治疗加双重治疗，共 2 次。
- 叶子位置 4、具大治疗、其余四只半血：大治疗自动触发，4 个有效治疗，冷却到 tick 561（首次 tick 1 + 28 秒）。
- 同样条件但恰为 60%：不触发大治疗。
- 位置 1 已倒地、其余伤者半血：只治疗三个存活伤者，不复活位置 1。
