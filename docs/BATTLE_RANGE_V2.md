# 战斗范围第二版

2026-09-08。本轮采用固定路线和站位下的范围修正，作为本地版本的当前运行参数。没有调整攻击力、治疗量、敌人强度、掉落或收录规则。最终平衡仍需完整章节试玩。

## 为什么调整

第四关位置 1 到 2 相距 4，原叶子龟在位置 2 可以治疗位置 1。此前对此处不可达的怀疑已经纠正。真正的问题是位置 4 到位置 2、3 均约 4.472，原叶子龟即使有远望也只有 4.3，普通治疗无法覆盖任何其他固定位置。鼓劲和分担原半径 3 也小于第四关任意两站位的距离，两技能在该布局无法保护友军。

另外，石龟在位置 1 首次挡下敌人时，该敌人到位置 2 约 4.587，超过原法师与控制职业的射程。它们可能等后续目标进入射程，利用溅射或弹射间接打到前敌，但这不能代替直接火力支援。详见 [第四关覆盖审查](FOURTH_LEVEL_COVERAGE.md)。

## 旧战斗恢复

- 存档封套、存档键与战斗结构版本仍为 1，不清空收藏或冒险。
- 新建波次标记 `balanceVersion: 2`。新单位从当前职业配置取得范围，鼓劲与分担从当前 `BATTLE_RULES` 取得范围。
- 没有此字段的历史战斗保持其已经保存的单位范围，鼓劲和分担继续使用 3。暂停、重载、备份恢复均不会悄悄升级正在进行的波次。该波结束后，下一波正常生成第二版。
- 解码与提交只允许未提供或数值 2；不接受其他版本标记。读取本身不写盘或增加 revision；原有检查点和结算仍正常持久化。
- `game/tests/fixtures/balance-v1` 来自提交 `cf544b813771c7a9334f885c52703c43acb949db` 的真实旧规则，记录 Git 来源与 SHA。专用测试用旧实现产生和继续战斗，与新实现恢复结果逐字段比较，覆盖五关、主档、备份和下一波切换。没有使用新实现生成所谓旧预期。

## 布阵提示

准备阶段选择龟时显示一条复用范围圈：远程为普通攻击圈、叶子为绿色普通治疗圈、石头为阻挡圈。替补没有场上范围圈。战斗、揭晓和结算不显示此规划提示；它不参与伤害、碰撞或目标选择。

## 平衡证据与边界

[8 种子比较](reports/COVERAGE_RANGE_COMPARISON.md)完成 752 波真实服务模拟，包括逐波保存恢复与重复结算检查。两组都完成五关；新范围使第五关首领击败由 6/8 提高到 8/8，末波队伍生命平均由 46.30% 提高到 87.17%。因此本改动对后期强度有明显影响。

这是固定策略、有限种子的成对比较，未搜索最佳布阵，不等于玩家胜率。模拟时长包含脚本准备时间，不含玩家阅读、思考、加载和暂停。普通四至六技能队伍能够完成章节仍是设计目标；不为恢复原有难度而保留失效的治疗或辅助技能。首领压力、不同首发职业以及实际关卡时长继续在完整章节验证中检查。
