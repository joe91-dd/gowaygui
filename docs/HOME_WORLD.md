# 首页展示与启动门控

`GameEntry` 已接入正式 `HomeWorld`，旧摄影棚、圆展台和单石龟旋转入口已删除。展示本身只读取首页场景与五龟模型，不依赖战斗、收藏或存档。

启动同时预载 `IslandIcons`、`IslandPanels` 和 `TurtlePortraits`；取得一次本地会话后创建首页世界。首次正式 UI 必须同时满足：

- `home.ready`：首页场景和五个正式 Prefab 均已完成装配。
- `panels.state === 'ready'`：面板图集和共享九宫格帧完整就绪。
- `portraits.ready`：五张正式角色头像全部就绪，四张不能通过。
- `icons.ready`：八个常用图标所在图集完整就绪，单独失败也不能放行。

首次等待与失败界面使用未注入正式面板和头像管理器的临时 `IslandUI`，只允许少量 Graphics 兜底；战斗返回时沿用已经就绪的正式 UI 与三批共享界面资源。显示玩家文案“海风正在把伙伴们带来…”“正在布置海岛…”“正在准备伙伴手册…”“正在整理冒险行囊…”，不展示资源数或内部格式。首次全部就绪且位于前台首页后，入口唯一一次换成：

```ts
this.ui = new IslandUI(this.ui.root, this.ui.click, this.icons, this.panels, this.portraits);
```

随后撤掉等待界面、显示海岛和正式入口。加载未完成时导航与进入战斗均受门控保护；没有可点击的空首页。第 4、5 参数分别为面板和头像管理器，战斗与收藏沿用这个正式 UI 实例。`interfaceReady` 仅代表正式 UI 健康可用；任何新的 `homeArrival` 都优先阻断页面渲染、导航、出发和菜单操作，不能被保留的 `interfaceReady=true` 绕过。

首次激活也是最后一道屏障：`HomeWorld` 在隐藏装配期间只校验动画片段，完整根节点激活并触发 Cocos `onLoad` 后才首次播放待机。入口在保留 arrival、暂停骨骼、尚未注入正式 UI 的同一次调用中激活并复查 ready，成功后才开放；若动画初始化失败则保留原错误/重试流程。不能在隐藏装配时假设 `getState()` 已存在，也不手动调用引擎 `onLoad`。214818 的实际首页错误已通过更真实的桩生命周期复现，后续构建另行复测。

失败需显式重试。仅失败的图标/面板/头像管理器调用自身 `retry()`；成功的批次和没有报错的首页世界保留。模型失败才销毁并重建世界。重试不重新获取会话、不构建新的存档服务、不重复冒险入场或广告奖励。没有 Promise 完成回调直接改写 UI；当前尝试、页面与前后台状态在入口更新中统一核对，旧按钮和迟到结果不能覆盖战斗页。`IslandIcons` 保留 `void preload()`，增加 `ready/error/retry()`；请求代号及重复回调防护使旧尝试无法覆盖新图集或重复获得源引用，失败与销毁都会使旧代号失效。

首页五个展示点与朝向来自 `environment/home-island/candidate-01/environment-manifest.json`，c02 保留五点；模型 scale 均为 0.65。场景路径为 `environment/home-island/home-island/home-island`，模型路径为 `models/<role>-turtle/<role>-turtle/<role>-turtle`。`HOME_CAMERA` 定义作者相机，入口保留窄窗 FOV 扩展与竖窗提示。

五个角色各自使用正式 Atlas 前缀，由 `TurtleMaterialAdapter` 转为原生 Standard。环境保留自身材质，下面只补顶面 Y=-0.72 的外海。`greet()` 播放每只空闲龟的 fusion，按各自完整时长回到 idle；重复点击不重播。应用后台隐藏且暂停，选关、收藏、详情、历史、设置等非首页菜单也隐藏整个首页根节点，保留资源但不提交它的 3D。菜单返回首页恢复原动作相位。`setReducedMotion()` 当帧取消进行中的招呼且保持当前暂停状态。

## 首页与战斗的资源交接

进入战斗的加载阶段只隐藏原首页。模型/海岛未到齐、后台等待、加载失败或玩家取消时，原首页仍保有自己的引用，返回即可复用。只有 `BattleScreen` 构造成功、`BattleWorld` 激活成功且模型仍就绪，入口才清空 `homeWorld` 并调用该首页实例的 `destroy()`。没有调用 `resources.releaseAll` 或强制释放共享龟纹理；战斗自己的资源引用继续有效。

`BattleScreen` 在构造中恢复暂停界面时可能同步报告检查点错误。入口先收集原始错误，构造返回后销毁失败控制器并保留原首页，不提前开放其 onHome/onError 回调身份；不存在读取尚未初始化 controller 的 TDZ。运行后的退出/错误回调只接受当前控制器。战斗加载页另有页面代号，旧返回/重试按钮和重复海岛回调不能覆盖后续页面。

成功战斗离开时仍先保存检查点；保存失败就留在战斗。保存成功后释放战斗控制器及世界，创建新的 `HomeWorld`，进入上述四资源及首次激活门控。健康的图标、面板、头像、正式 `IslandUI`、音频、会话和存档服务继续复用。返回加载时旧选队出发闭包在调用 `beginRun` 前检查页面/门控/弹窗有效性；旧菜单奖励操作也先检查门控。重复返回不新建额外到达尝试，失败只重建失败世界，后台就绪仍等前台，销毁后迟到结果不恢复页面。

销毁时三个 UI 所有者分别释放图标、头像、面板的共享纹理/帧；`HomeWorld.destroy()` 释放六个 Prefab 引用、转换材质、外海网格/材质和节点。四个所有者都阻止迟到加载重新挂载。

图标与头像的清理区分“已请求销毁”与“已经销毁”：仍有效的 pending Sprite 也须先清空共享帧。`NODE_DESTROYED` 事件先于组件最终销毁，监听必须走完整解绑；严格有效性判断仅用于新绑定和应用。

相关验证：`home-entry.test.cjs` 28 项、`battle-arrival.test.cjs` 13 项，包含保留 `interfaceReady=true` 时的返回门控、成功/失败交接、同步构造报错、旧回调、检查点失败和连续三轮往返。另运行 `home-world.test.cjs` 与图标/面板/头像生命周期测试共 46 项；本轮合计 87 项通过，Cocos TypeScript 检查通过。新用例曾对只读的 `3fe5726` 入口基线执行，40 项版本中 10 项失败，证明菜单显示、释放/重建、旧回调和重复挂载预期并非由旧实现满足；同步构造报错用例也先复现了 TDZ 再修复。

VM 测试验证实际 TypeScript 类的控制流程，不代表 Cocos 导入、GPU、最终画面或性能验收。220715 首页 18 FPS / 93.43 MiB、战斗 19 FPS / 139.70 MiB 为既有浏览器读数，详见 `HOME_RESOURCE_COST.md`；本轮未启动浏览器、Cocos 或 Blender，不预报内存下降幅度或 FPS 提升。下一构建应在同窗口、同第五关波次/阵容观察菜单 3D 提交、战斗接管后稳定纹理占用，以及三轮往返后的资源/错误日志和角色材质。
