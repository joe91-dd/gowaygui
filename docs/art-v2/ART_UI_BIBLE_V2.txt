《哥喂龟》正式 Art Bible / UI Bible V2
—— 已确认参考图统一执行说明（含“减少文字、清爽化UI”追加要求）

本消息同时附带的当前整套参考图（00～13）已经基本确认。

结论先说清楚：

1. 这套参考图的整体画面、画风、颜色、角色方向、场景气质、UI方向，我是满意的。
2. 不需要因为本条消息重新推翻、重新定风格、重新出另一套美术。
3. 你后续正式制作游戏内界面和素材时，应继续严格沿用这套参考图的整体视觉方向。
4. 但要额外重点优化一点：正式游戏中要明显减少文字量，让界面更清爽、更轻松、更不累眼。

==================================================
一、总原则
==================================================

当前这套参考图共同定义了《哥喂龟》的正式视觉方向。

后续制作请继续保持：

- 高品质3D风格化奇幻海岛
- 可爱但不幼稚
- 面向全年龄、全球化
- 海洋冒险感
- 明亮、清爽、有品质
- 角色有收藏欲
- 场景丰富但不过载
- UI统一且清晰

不要另起一套新风格。

不要因为继续做页面而逐渐偏离当前这套参考图。

==================================================
二、00～13 参考图继续作为正式基准
==================================================

当前这套参考图继续作为项目正式 Art Bible / UI Bible 使用。

你应继续按照此前已经明确的职责理解它们：

- 总美术基准图：定义整体世界观和总气质
- 登录界面图：定义登录页方向
- 主界面图：定义主城/海岛广场布局和表现
- UI组件图：定义按钮、面板、资源条、图标、品质框等
- 五角色设定图：定义正式角色造型
- 战斗图：定义战斗场景、HUD、技能栏、技能特效
- 合成流程图：定义宠物合成、揭晓、结果展示流程
- 我的龟龟图：定义收藏页方向
- 商城图：定义商城结构和礼包呈现方式
- 无尽图：定义无尽入口与奖励呈现方式
- 竞技场图：定义竞技场结构与视觉方向
- 当前功能实机图：只作为现有功能和玩法的真实来源，不作为旧美术参考

后续没有单独参考图的页面，也必须沿用当前这套视觉体系自动延伸。

==================================================
三、这次新增的最重要要求：正式游戏“减少文字量”
==================================================

这一点非常重要。

虽然当前参考图整体我满意，
但这些参考图里存在一个不希望正式游戏继续保留的问题：

“页面上的字太多，口号和装饰性文案太多，看起来容易累、容易乱。”

因此请在正式实现时，主动进行“减字优化”。

==================================================
四、减字优化的明确执行标准
==================================================

正式游戏中，以下内容尽量减少或直接去掉：

1. 页面上的口号
2. 装饰性广告语
3. 长句宣传文案
4. 对同一功能的重复解释
5. 不影响操作理解的英文装饰字
6. 不必要的大段说明文字
7. 仅用于“填空白”的无意义文字
8. 同屏过多分类标题
9. 可以图形化表达却仍然写成长文的内容

原则是：

“能用图表示，就少用字。”
“能短写，就不要长写。”
“能二级展开看，就不要全堆在首页。”
“能靠图标、颜色、品质框、头像、道具图表达，就别写成长句。”

==================================================
五、哪些文字必须保留
==================================================

减少文字，不等于完全不要文字。

以下必要文字应保留，但要尽量简洁：

1. 核心入口名称
   例如：
   - 开始冒险
   - 我的龟龟
   - 合成工坊
   - 交易行
   - 租赁市场
   - 商城
   - 排行
   - 好友
   - 无尽
   - 副本
   - 竞技场

2. 核心数值标签
   例如：
   - 金币
   - 体力
   - 攻击资质
   - 生命资质
   - 防御资质
   - 成长

3. 关键操作按钮
   例如：
   - 购买
   - 确认
   - 取消
   - 去合成
   - 上阵
   - 下阵
   - 使用
   - 保存
   - 改名
   - 返回

4. 关键系统状态
   例如：
   - 已锁定
   - 稀有
   - 史诗
   - 传说
   - 今日限购
   - 波次
   - 胜利
   - 失败

5. 玩家必须知道、否则无法理解玩法的核心说明
   但这类说明要尽量：
   - 短
   - 集中
   - 按需显示
   - 不占主画面

==================================================
六、各页面的减字规则
==================================================

--------------------------------------------------
1. 主界面 / 海岛广场
--------------------------------------------------

主界面要尽量清爽。

可以直接去掉：

- 口号
- 宣传语
- 场景上的大段装饰文字
- 不影响功能理解的说明句
- 类似“更好的世界”“更大的冒险”“守护希望”等装饰性文案

主界面重点保留：

- 玩家头像/名字
- 金币/体力
- 建筑名称（短）
- 开始冒险
- 底部模式快捷入口
- 聊天窗口
- 红点提示

聊天默认只显示少量简短内容，不要占太大面积。

--------------------------------------------------
2. 登录界面
--------------------------------------------------

登录界面尽量简洁。

保留：
- 游戏标题/Logo（如当前项目需要）
- 主要角色展示
- 登录方式按钮
- 公告 / 用户协议 / 隐私等必要入口

去掉：
- 大段宣传口号
- 过多场景文案
- 过多英文装饰句
- 大块说明性文案

登录界面重点应是：
“角色 + 世界观 + 登录入口清晰”。

--------------------------------------------------
3. 我的龟龟
--------------------------------------------------

列表页不要堆太多字。

优先用以下方式表达信息：

- 品质框颜色
- 角色头像/立绘
- 职业图标
- 技能图标
- 数值条
- 简短标签

列表卡片上尽量只保留：
- 名字
- 品质
- 职业
- 关键战力信息或技能数
- 必要的小标签

详细技能描述、来源说明、个体说明等，
放到点击后的详情区，不要全部挤在列表卡片上。

--------------------------------------------------
4. 商城
--------------------------------------------------

商城也要减字。

每个商品卡尽量只保留：
- 商品图标/礼包图
- 商品名称
- 售价
- 每日剩余可购买次数
- 购买按钮

概率说明不要默认整屏展开。

正确做法：

- 主界面商品卡上简洁展示
- 概率详情做成：
  - “概率”按钮
  - “详情”弹窗
  - 二级说明面板

不要把所有概率长文直接铺满商城主页面。

--------------------------------------------------
5. 无尽模式
--------------------------------------------------

无尽页重点保留：
- 当前最高波次
- 推荐阵容/推荐战力（如已有）
- 主要产出图标
- 阶段奖励图标
- 开始挑战
- 规则入口

不要在主页面直接写很多规则说明。

规则应收纳到：
- 规则按钮
- 小问号说明
- 二级弹窗

--------------------------------------------------
6. 竞技场
--------------------------------------------------

竞技场主页面重点保留：
- 当前段位
- 当前积分
- 对手列表
- 我的阵容
- 防守阵容
- 开始挑战
- 刷新
- 赛季奖励入口
- 排行入口

不要在主界面铺太多说明文字。

段位说明、结算规则、奖励规则等，
放到二级说明入口。

--------------------------------------------------
7. 战斗界面
--------------------------------------------------

战斗界面必须尽量“少字”。

优先靠以下内容表达：

- 血条
- 技能图标
- 颜色
- 特效
- 波次
- 计时
- 1X / 2X
- 暂停图标
- 一键释放按钮
- 目标高亮
- 怪物头顶信息

战斗中不要出现大段文字提示反复干扰。

除非是：
- 教学第一局
- 关键功能第一次出现
- 重要失败/胜利信息

即便要提示，也尽量做短句。

--------------------------------------------------
8. 合成揭晓界面
--------------------------------------------------

合成界面也不要堆字。

重点靠：
- 两只亲本形象
- 大型五彩泡泡
- 新龟模型
- 品质框
- 技能图标
- 资质与成长数值模块

文案保持最简。

例如当前提示：

“涂抹擦除或单击戳破揭晓结果”

这种就属于可以接受的必要提示。

但不要再额外叠加一堆口号、感叹句、装饰句。

==================================================
七、图标优先原则
==================================================

后续正式游戏中，尽量优先使用图标表达信息。

例如：

- 金币：直接用金币图标 + 数字
- 体力：闪电/体力图标 + 数字
- 邮件：信封图标
- 设置：齿轮图标
- 排行：奖杯图标
- 好友：人物/爱心图标
- 品质：边框颜色
- 职业：职业图标
- 技能：技能图标
- 稀有度：颜色 + 简短标签

不要所有内容都靠一长串字解释。

==================================================
八、短文案标准
==================================================

必须显示文字时，尽量使用短文案。

优先级：

1. 单个词
2. 2～4个字短词
3. 极短短句

例如：

优先使用：
- 开始冒险
- 去合成
- 确认
- 返回
- 购买
- 使用
- 规则
- 详情
- 概率
- 上阵
- 升级

尽量避免：
- 很长的宣传式文案
- 很多修饰词
- 一眼看不过来的长标题

==================================================
九、页面信息层级规则
==================================================

正式游戏信息展示应分层：

第一层：玩家最常用、最重要的信息
- 入口
- 货币
- 体力
- 主要按钮
- 当前阵容/商品/奖励概览

第二层：补充信息
- 排序
- 筛选
- 标签
- 稀有度
- 辅助说明

第三层：详细信息
- 技能详细说明
- 概率详细表
- 规则长说明
- 物品来源
- 系统帮助

第三层不要默认全部铺在主画面。

==================================================
十、当“参考图文字多”与“正式减字要求”冲突时
==================================================

如果某张参考图里本身画了较多文字，
而这些文字属于：

- 口号
- 装饰文案
- 广告语
- 长说明
- 英文装饰句

则正式制作时：

可以删减，
可以简化，
可以隐藏到二级层，
可以用图形/图标替代。

也就是说：

当前参考图的
“画面、画风、颜色、角色、建筑、UI气质、布局”
继续保留；

但其中的
“过多文字”
在正式版本中应主动做减法优化。

==================================================
十一、功能优先复用，视觉继续统一
==================================================

继续保持此前原则：

- 当前已通过测试的玩法和功能继续保留
- 尽量复用已有代码、数据、页面逻辑
- 不要因为换UI重写无关业务系统
- 不要因为减字而改变玩法
- 只优化表现层、页面层级、信息呈现方式

没有参考图的新页面，也继续按照当前这套视觉系统延伸，
同时遵守“少字、清爽、图标优先”的新要求。

==================================================
十二、后续具体实施要求
==================================================

你在继续制作正式游戏页面时：

1. 继续按当前整套参考图统一风格。
2. 主动减少多余文字。
3. 直接删去可删的口号和广告语。
4. 能用图标表达的地方优先改为图标表达。
5. 长说明尽量收纳到二级弹窗或详情页。
6. 列表页和首页不要堆叠太多文字说明。
7. 保持界面清爽，不要让玩家看着很累。
8. 不要因为减字把功能入口做得难理解，必要短文字仍然保留。
9. 中文界面优先。
10. 非必要英文装饰可以不做，或大幅减少。

==================================================
十三、最终目标
==================================================

最终我想要的不是“参考图文字版原样照搬”，
而是：

在保持当前整套参考图的
画面、画风、颜色、角色设定、建筑语言、UI方向
都不跑偏的前提下，

把正式游戏做成一个：

- 更清爽
- 更少字
- 更轻松
- 更不杂乱
- 更适合长期游玩的版本

也就是：

保留现在我满意的视觉方向，
但把正式产品的信息噪音压下去。

这条要求从现在开始纳入后续所有正式页面制作中统一执行。
