# 海岛副本房间与账号服务

2026-09-15 新增配套账号、按区云存档、好礼领取、广告验证接口和反馈工单。游戏设置中的「账号与服务」可注册、登录、切换、修改密码及反馈。账号数据独立保存在 `rooms.json.accounts.json`；原游客进度不会删除。完整政策及接入限制见 `output/release-polish-20260915/奖励广告分享与账号接入.md`（从项目根目录访问）。

激励广告需配置 `REWARDED_AD_URL` 和 `REWARDED_AD_SECRET`；未配置时前端明确显示尚未接入，不会模拟观看成功。平台适配后端以 `nonce`、`transactionId`、`signature` 调用 `POST /api/account/ad-callback`；签名为 HMAC-SHA256(secret, nonce + ':' + transactionId)。回调由服务端验证，密钥不得放在前端。`GAME_SUPPORT` 可配置客服信息；反馈工单当前保存在账号数据队列中，需要接入真实客服人员或系统。

## 启动

在工程根目录执行：

```powershell
./game/server/Start-RoomService.ps1
# 允许同一局域网的其他设备连接：
./game/server/Start-RoomService.ps1 -Port 7470 -Lan
```

本机默认地址为 `http://127.0.0.1:7464/`。其他设备使用这台电脑的局域网 IPv4 地址和端口；不要在手机上填写 `127.0.0.1`。系统防火墙需要允许该端口的局域网连接。脚本不会自动修改防火墙或发布到公网。

默认运行 `game/build/living-expedition`，启动前编译共享战斗规则。Node 与 Cocos 编译器路径在启动脚本顶部，可按安装位置修改。停止：`./game/server/Stop-RoomService.ps1`。升级时先正常结束战斗；停止脚本会终止本服务进程，最近两秒尚未刷盘的状态可能丢失。

## 已实现

- 每人五只备战宠物，同时控制一只；五人房间，真人使用六位邀请码加入或匹配已开放的房间。
- 队长可以开放/关闭匹配、邀请在线玩家、移出成员和手动补 AI。不会把 AI 显示为真人。
- 每位真人准备后才能开局；服务器统一以 20 Hz 推进战斗，校验技能、换宠、调位的操作归属。
- 换宠保留血量和冷却。拖到已占位置时交换位置；路径、障碍物、海面不能落点。
- 房间、玩家身份、战斗和待发邮件每两秒写入 `data/rooms.json`，重启可恢复；已完成奖励采用唯一编号，在客户端存档成功后才确认送达。
- 基础奖励通过系统邮件领取；星级箱保存在副本“我的宝箱”；经验直接结算到参与战斗的自有宠物。

游戏存档仍在各客户端浏览器中，房间身份也按浏览器保存。不要清除网站数据。同一浏览器标签页可能共用身份，测试不同玩家请使用不同浏览器配置或不同设备。房间数据文件包含访问凭证，备份时应视为私有数据。

这是配套本地/局域网服务。宠物来自客户端存档，尚不具备公网正式服的账号认证、服务器养成存档校验、反作弊、集群和全服排位。竞技场当前仍为本地 AI 对手；周结算在在线检查或下次登录时补发邮件，不会虚构其他真人玩家。

## 后续系统邮件

启动服务前设置环境变量 `ROOM_ADMIN_TOKEN` 为管理员自己保存的随机凭证。向同源服务发送 `POST /api/admin/mail`，使用 `Authorization: Bearer <凭证>`，请求体示例：

```json
{"id":"maintenance-20260914","clientId":"收件玩家ID","title":"维护补偿","body":"感谢等待。","grants":[{"kind":"gold","amount":1000}]}
```

`all:true` 可替代 `clientId`，仅发给已经在该服务注册的玩家。`id` 必须唯一；重复相同编号不会重复发放。金币附件使用改版后的实际金币数。还支持 `material`、`book`、`bookPack` 奖励，结构由 `core/rewardPacks.ts` 校验。管理员凭证不要放入客户端代码。

健康检查：`GET /api/health`。所有房间 API 使用注册返回的 Bearer 凭证，跨站 Origin 请求会被拒绝。
