# 哥喂龟目标模式指令

当前任务已按下列目标运行；此文件供保存和查阅，无需在当前任务重复提交。

使用方法：在本项目的 Codex 任务中选择 GPT-6 Astra 和界面提供的最高推理强度，然后完整粘贴下面从 `/goal` 开始的内容。

```text
/goal 在当前工作区完成《哥喂龟》小体量、接近发行品质的 3D 单机成品。在达到下述可验证完成条件前持续推进，不要只输出计划、代码片段、概念图或无法运行的演示。

开始前必须完整阅读并遵循：
1. output/哥喂龟游戏设计讨论稿-v0.5.docx
2. output/开发阶段约定-2026-09-08.md
3. output/art/A-潮汐玩具岛.png
4. output/art/A3-五官区分场景参考.png
5. output/art/A4-五龟三男两女角色参考.png
6. output/A4角色图提示词.md

若文件之间存在冲突，以日期更晚的《开发阶段约定》以及本目标为准。保留原有讨论文档和美术参考，不覆盖或删除它们。

技术范围：
- 使用电脑中现有的 Cocos Creator 3.8.8，以 TypeScript 建立可继续发布到微信和抖音小游戏的同一工程，项目放在 game 目录。
- 第一阶段交付本地浏览器可玩的单机成品。暂不接真实微信或抖音登录、真实广告、生产服务器、公开排行榜、无尽模式、PVP、租借和商业发布。
- 平台登录、广告、存档与战斗逻辑分层；数值配置化；不得为本地版本采用以后必须整体推翻的专用架构。
- 不信任本地存档作为未来生产安全方案。测试存档默认不进入正式经济或排行榜。

游戏内容：
- 完成五只 3D 龟：石头龟男、刺刺龟男、水晶龟女、叶子龟女、泡泡龟男。保持 A 方向的头身比例、龟壳材质、配色与玩具质感，仅按讨论稿区分五官和性格。
- 完成一关 2～3 分钟教学、三关 4～6 分钟普通关和一关 6～8 分钟首领关，共五关，组成一个可从头玩到尾的海岛章节。
- 实现完整主界面、关卡选择、我的龟龟、龟详情、培养、战斗、合成、擦泡泡揭晓、收录对比、历史、暂停、设置和结算。
- 实现最多五只在场和五只替补、五职业配合、布阵、敌人波次、首领、金币、体力、本地存档、三项资质加成长、局内等级和原型技能表。
- 十二项永久技能必须全部真实生效，不得暗中改成只装备或生效六项。普通内容以四至六技能可完成为目标，十二技能是长期稀有追求。
- 永久收藏 A、B 的本局个体合成 C 后，不收录 C 时永久 A、B 保留且下局仍可使用；确认收录 C 后，实际参与的永久来源才转为历史。合成和收录必须是可恢复的两个步骤，同局不得无限复制来源重抽。
- 广告入口只用明确标注的本地模拟按钮验证体力、金币翻倍和一次招募刷新流程；合成确认、揭晓和收录过程不出现广告。

美术和声音：
- 纳入这五关的角色、敌人、首领、场景、界面、图标、特效、动画、音乐和音效均按预定正式品质完成，能够延续到平台版本。最终交付中不得残留方块、胶囊、默认按钮、调试文字或未经整理的占位资源。
- 开发过程中允许短暂使用占位资源验证功能，但必须建立清单并在最终验收前全部替换。
- 五只龟至少具有待机、普攻、主动技能、受击、休整和合成反应动画。技能效果在手机尺寸下可辨认，不能以堆叠粒子掩盖战斗信息。
- 完成主界面音乐、普通战斗音乐、首领或高压阶段音乐各一套，并完成界面、攻击、受击、五职业技能、擦泡泡、收录、胜利、失败和稀有结果音效。提供音乐、音效分别调节与静音功能；暂不制作角色配音。
- 资产须原创或有明确可商用授权。保存模型、贴图、动画、音乐、音效的可编辑源文件及来源清单。不得模仿、提取或改造其他游戏的角色、界面、音效、音乐、图标和演出素材，也不得把 AI 输出自动视为已完成排他性权利审查。

工具授权与限制：
- 先检查现有环境。Cocos Creator 3.8.8 已安装在 C:/ProgramData/cocos/editors/Creator/3.8.8/CocosCreator.exe。
- 为完成本项目，允许从软件官网获取必要的免费开源便携工具，例如 Blender LTS、Krita、Audacity 及必要的命令行音频或图片处理工具；优先下载到工作区的 tmp/tools 并校验来源，不纳入 Git，不安装驱动、服务、浏览器扩展，不改变系统默认程序，不下载破解软件或来源不明的插件。系统级安装、账号登录、许可协议购买或需要管理员权限时暂停并说明具体原因，等待用户处理。
- 可以使用内置图像生成能力制作本项目原创概念和纹理素材，但真正的 3D 角色必须交付模型、骨骼、动画和可编辑源文件，不能把二维概念图假装成完整 3D 模型。
- 不购买付费素材，不对外发布，不创建收费服务。确需预算或外部专业服务时，先提供可审查的需求、费用和替代方案，等待用户决定。

工作方式：
- 首先审计文档、环境和工作区，建立 PLAN.md、验收清单、风险清单、资产清单和简短进度日志，然后立即继续实现，不要在写完计划后停止。
- 按可验证检查点推进：工程与构建管线；核心战斗；合成与收录；首个最终品质角色和代表场景；五只龟与完整第一章；界面与声音；平衡、性能、存档和最终验收。
- 美术样板确定后再批量制作同类资产。遇到会显著改变 A 风格、核心玩法、收录规则或预算的选择时，先产出可查看的方案和对比，再等待用户决定；常规实现选择自行判断。
- 每个检查点运行适当的自动化检查和实际构建。持续修复错误，不以“理论上可运行”代替运行结果。保持提交或等效可回滚记录，不破坏用户已有文件。
- 进度更新只说明当前检查点、已经验证的结果、下一步和真实阻塞，不重复长篇计划。

完成条件：
1. Cocos Creator 3.8.8 工程可以打开并成功构建本地 Web 版本，构建产物可启动，从新存档到通关五关不存在阻断流程的错误。
2. 玩家可以完成获得龟、布阵战斗、升级、局内合成、擦泡泡揭晓、比较、暂不收录或确认收录、培养、保存、退出和恢复的完整循环。
3. 用自动测试和可复现用例证明十二技能全部生效、概率表合计正确、技能无循环触发、金币体力不会重复发放、收录规则和多代来源在重启及异常中断后保持正确。
4. 纳入范围的所有可见美术、动画、界面、音乐和音效达到一致的正式风格；不存在交付占位物、明显乱码、裁切、错误层级、破音或缺失资源。提供可审查截图或录屏以及资产清单。
5. 在本机浏览器实际检查教学和五关流程，记录关卡时长、主要帧率、内存、加载时间和明显体验问题；对发现的问题完成修复或明确记录无法在当前环境验证的限制。
6. 提供 README、启动与构建说明、操作说明、数值与存档说明、测试报告、第三方与生成资产来源清单、已知问题、平台适配待办和可继续编辑的源文件。
7. 最终提交一份用户验收包，清楚列出如何启动、建议试玩顺序及需要用户主观确认的画面、声音和手感。只有可运行验收包、验证记录和源文件均齐全时才可报告技术工作完成；审美、乐趣和正式发布仍以用户验收为准。

如果缺少必要的人类登录、验证码、管理员批准、付费许可或只有用户能作出的审美决定，完成所有不依赖该事项的工作后再暂停，并精确说明需要用户执行的一步。不要因为困难、耗时或额度接近上限而自行缩小范围或宣布完成。
```
